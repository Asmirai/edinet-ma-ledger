# シミュレーターを、ブラウザだけで動く静的なページにする

- issue：#38
- PR：#45、#46

## 決めたこと

失敗確率のシミュレーター（`site/`）は、サーバーを持たない静的なページにし、GitHub Pages で公開する。確率は、Python で学習した係数を `site/model.json` に書き出し、ブラウザの JavaScript（`site/model.js`）が同じ式で計算する。

## なぜ

| 決めたこと | なぜ |
|---|---|
| サーバーを持たない | 入れた数字（自社の総資産や買収の候補）をブラウザの外に送らずに済む。動かし続ける費用もかからない |
| 係数だけを書き出し、計算は JavaScript で書き直す | モデルはロジスティック回帰なので、標準化と係数の掛け算で確率が出る。Python をブラウザで動かす（Pyodide）と、読み込みに数十 MB かかる |
| ライブラリを使わず、素の JavaScript と SVG で描く | 曲線1本と棒5本の図に、描画のライブラリは要らない。依存の更新も要らなくなる |
| Python と同じ確率になることを、Node のテストで確かめる | 式を2か所に書くので、ずれが生じうる。例の候補4社の確率が Python と1e-12まで一致することを、CI と Pages の公開の前に確かめる |

## 採らなかった案

Streamlit で作り、Streamlit Community Cloud に置く案は成立する。採らない。入れた数字がサーバーに送られるうえ、しばらく使われないとアプリが止まり、開くたびに起動を待たせる。

## 経緯

#45 で、CI の `node --test site/` が Node 22 ではフォルダを受け付けず失敗したのに、パイプで終了コードが隠れてマージしてしまった。#46 でテストのファイルを直接渡すように直し、マージの前には `gh pr checks` の終了コードを確かめるようにした。
