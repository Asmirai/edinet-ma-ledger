# モデルカード：のれんの減損を予測するモデル

`ledger/scorer.py` のモデルは、買収の候補ごとに、買収から3年以内にのれんを減損する確率を見積もります。上場企業の買収1,719件で学習したロジスティック回帰です。**確率は候補を順に並べるのには使えますが、値そのものは危ない候補ほど低めに出ます。** 買収をするかどうかを、このモデルだけで決めないでください。

## 用途

使ってよい用途は次の2つです。

- 買収の候補を、のれんを減損しやすい順に並べる材料にする
- 記事（[Qiita](https://qiita.com/ykuchiki/items/18d31329d81581d56a61)）の結果を、公開 CSV から再現する

次の用途には使わないでください。

| 使ってはいけない用途 | 理由 |
|---|---|
| 確率の値を、その買収が失敗する確率として扱う | 較正が合っていません。危ない側の群で、実際の失敗率より約10ポイント低く出ます（下の「較正」） |
| 買収をするかどうかを、このモデルだけで決める | 入っている変数は4つだけです。相手の事業の将来性と、買収後の統合の計画は入っていません |
| 減損以外の失敗（シナジーが出ない、主要な人材が辞める）を予測する | 目的変数はのれんの減損だけです |
| 非上場企業どうしの買収、海外の会社が買い手の買収に当てはめる | 学習したのは、日本の上場企業が有価証券報告書の注記に載せた買収だけです。それ以外への当てはまりは未検証です |
| 上乗せ率が1.5を超える候補に使う | 学習した範囲の外です。`deal_inputs` は ValueError で止めます |
| 特定の会社の経営の良し悪しを評価する | 下の「倫理上の注意」 |

## データ

学習には、公開 CSV（Release `ledger-2026-10` の `ma_ledger.csv`）だけを使います。列の意味は [ma_ledger_csv.md](ma_ledger_csv.md) にあります。

台帳は、有価証券報告書（2016年10月〜2025年9月提出）の「企業結合等関係」の注記から、Claude Code のサブエージェントが買収を抜き出したものです（6,405行、買収6,324件）。このうち、次の条件をすべて満たす1,719件（2017〜2022年度の買収）で学習します。

- `primary` が True（親会社と子会社が同じ買収を載せたときは、買収前の総資産が小さいほうの1行。直接買った子会社であることが多い）
- のれんが生じ、減損したかどうかを判定できた（`goodwill_impaired` が True か False）
- 企業結合日を含む事業年度（`base_year`）が2022年度まで。それより後は、3期後の有価証券報告書がまだ出ていません
- のれん ÷ 取得原価が1.5以下（超える行は単位の読み違いが多いため除く）
- 4つの説明変数がそろう

のれんが生じ、減損を判定できた買収は2,429件あり、そのうち15.6%が減損しました。1,719件は、このうち4つの変数がそろうものです。

## 説明変数

買収の前に、買い手が集められる4つの値です。

| 変数 | 台帳での値 | 候補で入れる値 |
|---|---|---|
| 上乗せ率 | のれん ÷ 取得原価 | （買収額 − 取得する持分に当たる相手の純資産）÷ 買収額。0未満は0にする |
| 規模 | 取得原価 ÷ 買い手の買収前の期の総資産、の対数 | 買収額 ÷ 自社の総資産、の対数 |
| 自己資本比率 | 買い手の買収の直前の期の有価証券報告書から読んだ値 | 自社の自己資本比率（0〜1） |
| 業種の関係 | 注記の「企業結合を行った主な理由」を AI が分類した、同業種・関連業種・異業種 | 同業種・関連業種・異業種のどれか |

数値の3つは標準化し、業種の関係は one-hot にして、scikit-learn の `LogisticRegression` の既定の設定で学習します。

4つは、全期間のデータを見て選びました。同じ学習と確かめの分け方で、目的・対価の種類・買い手の現金比率・買収前の ROA（同業の中央値との差）を足しても、AUC は0.684で、4つの0.687とほとんど変わりませんでした（欠けた値は平均で埋めた）。この4つの列は公開 CSV に無いので、この比較は公開 CSV からは再現できません。

## 目的変数

買収した期から3期後までに、その買収で生じたのれんを減損したか（`goodwill_impaired`）です。子会社株式の減損に伴うのれんの一時償却も、減損に含めます。

減損は、有価証券報告書に決まった置き場所がありません。買収後3期の有価証券報告書から「減損」と相手の名前の両方を含む箇所を機械で拾い、拾えた箇所を AI に確かめさせました。拾えるのは、相手の名前と並べて書かれた減損だけです。そのため、減損は実際より少なめに出ている可能性があります。

買い手全体の ROA を目的変数にしなかった理由は、[decisions/17-impairment-target.md](decisions/17-impairment-target.md) にあります。

## 学習と検証の方法

時系列のホールドアウトで確かめました。2019年度までの850件で学習し、学習に使っていない2020年度以降の869件で確かめます。

`uv run python -m ledger.scorer examples/candidates.csv` で候補の確率を出すときは、1,719件すべてで学習したモデルを使います。

## 性能

確かめの869件で、AUC は0.687でした。869件の失敗率は17.3%です。

確率の低い順に5つの群に分けると、失敗率は次のようになりました。

| 確率の低い順の群 | 件数 | 失敗率（実際） | 確率の平均（モデル） |
|---|---|---|---|
| 1 | 173 | 2.9% | 7.5% |
| 2 | 174 | 12.6% | 10.2% |
| 3 | 174 | 17.8% | 12.5% |
| 4 | 174 | 23.0% | 15.2% |
| 5 | 174 | 29.9% | 20.4% |

いちばん低い群といちばん高い群の失敗率には、約10倍の差がつきました。

## 較正

確率の値は、実際の失敗率と合っていません。いちばん低い群では、モデルの確率（7.5%）が実際（2.9%）より高く出ます。高い群では低く出て、いちばん高い群ではモデルの20.4%に対して実際は29.9%でした。学習した2019年度までの買収のほうが、確かめた2020年度以降より減損率が低いことが一因です。

較正し直す処理（Platt scaling や isotonic regression）は入れていません。

## 限界

- **変数の選び方**：4つの変数は、確かめの期間を含む全期間のデータを見て選びました。2019年度までのデータだけで見ても、4つとも同じ向きの差が出ます
- **学習と確かめの期間の重なり**：2019年度の買収の成否は、3期後の2022年度まで決まりません。学習に使った成否の一部は、確かめの期間に分かったものです
- **相関であって因果ではない**：上乗せ率を下げれば減損しにくくなる、とは言えません
- **抜き出しの誤り**：台帳の値は AI が抜き出したものです。156件を原文と見比べた抜き取りでは、取得原価の誤りは2件（1.3%）でした。このうち30件は ChatGPT にも採点させて突き合わせました。人による確認はまだしていません
- **減損の拾い漏れ**：上の「目的変数」のとおり、減損は少なめに出ている可能性があります
- **対象の偏り**：重要性が乏しいとして注記を省いた買収は入っていません

## 倫理上の注意

- 台帳には実在する上場企業の名前が入っています。のれんの減損は、買収の時点の見積もりが外れたことを示す会計処理で、経営の失敗を断定するものではありません。特定の会社を批判する材料にしないでください
- 予測は、過去の似た買収の傾向を示すだけです。個別の会社や個別の買収について、モデルの確率を根拠に断定しないでください
- 台帳は、EDINET のデータを合同会社Asmirai が加工したものです。使うときは、README の出典と加工の記載を表示してください（公共データ利用規約（第1.0版））

## 更新の方法

新しい年度の有価証券報告書が出たら、次の順に作り直します。

1. README の「データの取得から作り直す」の手順で、台帳を作り直す
2. 成否を判定できる年度が進んだら、`ledger/public.py` の `LAST_BASE_YEAR` を進める。学習と確かめの境目（`ledger/scorer.py` の `LAST_TRAIN_YEAR`）を動かすかも決める
3. `uv run python -m ledger.export` で公開 CSV を書き出し、新しい Release に添付する
4. `uv run python -m ledger.scorer` で `data/scorer.md` を書き直し、このカードの件数・AUC・群の表を書き換える
5. 変更を [CHANGELOG.md](../CHANGELOG.md) に書く
