# 企業結合の注記から案件を抜き出す

入力ファイル（JSONL、1行1注記：docID・filerName・element・text）を Read で全部読み、注記ごとに案件を抜き出して、出力ファイルに Write で JSON を1つ書く。コードやスクリプトは書かない・実行しない。あなた自身が文章を読んで判断する。

## 出力の形

```json
[
  {"docID": "...", "element": "...", "deals": [ {案件}, ... ]},
  ...
]
```

入力の全行について1要素ずつ、入力と同じ順で出す。案件が無い注記は `"deals": []`。

案件の項目：

- `acquiree_name`：相手の会社名・事業名。原文の表記のまま（「株式会社」等も原文どおり）。事業分離（売却）では、手放した事業・会社の名前
- `kind`：`"取得"`（グループ外の会社・事業を買った M&A）／`"共通支配下の取引"`（グループ内の合併・会社分割・子会社株式の追加取得など）／`"その他"`（事業分離＝売却、取得関連の暫定処理の確定だけの記載など）
- `period`：`"当期"` か `"前期"`。前連結会計年度（前事業年度）の欄に書かれた案件だけ `"前期"`
- 以下は `kind` が `"取得"` のときだけ埋める。それ以外はすべて null
  - `business`：相手の事業の内容（原文のまま）
  - `acquisition_date`：企業結合日（原文のまま）
  - `legal_form`：企業結合の法的形式（原文のまま。例「株式取得」「現金を対価とする株式取得」）
  - `voting_ratio`：取得後の議決権比率（原文のまま。例「100％」）。取得前・追加取得の内訳があれば取得後の合計
  - `consideration`：取得原価（取得の対価の合計）。段階取得では、取得前から持っていた持分の時価を含めた「取得原価」の合計が書かれていればそれ、無ければ支払った取得の対価
  - `goodwill`：発生したのれんの金額。負ののれんは null
  - `assets_total`：企業結合日に受け入れた資産の合計（資産合計の行の値。のれんを含む合計でもそのまま入れる）
  - `proforma_sales`：期首に取得していたと仮定したときの売上高（売上収益）への影響の概算額（差額）。会社全体の額しか書かれていなければ null。「重要性が乏しいため記載を省略」なら null
  - 金額は `{"value": "1,410", "unit": "百万円"}` の形。value は原文に書かれた数字の文字列をそのまま（全角・カンマ・△もそのまま）、unit は「円」「千円」「百万円」「億円」のどれか（表の見出しなどに書かれた単位）
  - 書かれていない項目は null

## 守ること

- **数字や名前を作らない。** 原文にそのまま載っている文字列だけを書く。計算・換算・推測で埋めない。迷ったら null
- 前期以前の取得について、当期に暫定的な会計処理の確定・条件付取得対価の調整だけを書いた記載は、`kind` を `"その他"`、`period` を `"当期"` とする1件にする。同じ注記の前期の欄に取得そのものの記載があれば、それは別に `"取得"`・`"前期"` の1件にする
- 複数の取得の金額が合計でしか書かれていなければ、その金額は各案件とも null
- 外貨だけで書かれた金額（例「USD 12百万」）は null
- 1つの注記に複数の取得があれば、それぞれ1件にする。同じ案件を2件にしない
- 「取得による企業結合」の見出しでも、中身が既存子会社の追加取得なら「共通支配下の取引」

最後に、書いた件数（注記数と、kind ごとの案件数）を1行で返す。
