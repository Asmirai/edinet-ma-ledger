# 買収の目的と、買い手の事業との近さを分ける

入力ファイル（JSONL、1行1案件）を Read で全部読む。各行には次が入っている。

- `key`：案件の番号
- `acquirer`・`acquirer_industry`：買った会社の名前と業種（東証の33業種）
- `acquiree_name`・`business`：買われた会社（または事業）の名前と事業の内容
- `reason`：有報の注記の「企業結合を行った主な理由」の部分（300字まで。途中で切れていることがある）。見つからなかった案件は null

コードやスクリプトは書かない・実行しない。自分で読んで判断する。

## purpose（買収の目的）：次のどれか1つ

- `同じ事業の拡大`：今の事業と同じ事業で、顧客・店舗・シェア・生産能力を増やす
- `新しい事業への参入`：今は手がけていない事業・分野に入る
- `地域の拡大・海外進出`：同じ事業を、新しい地域や海外に広げることが主な目的
- `仕入れ・販売の取り込み`：仕入れ先や販売先を取り込む（垂直統合）
- `技術・人材の獲得`：技術・ノウハウ・開発力・人材を得ることが主な目的
- `再建・救済`：経営が苦しい会社の支援・再建
- `その他`：上のどれにも当てはまらない、または読み取れない

複数書かれていれば、最初に書かれた目的か、いちばん強く書かれた目的を選ぶ。`reason` が null なら、`business` と買い手の業種から判断し、読み取れなければ `その他`。

## relatedness（買い手の事業との近さ）：次のどれか1つ

- `同じ事業`：買い手の主な事業と同じ事業
- `近い事業`：同じ業界の別の工程・隣の分野、または同じ顧客に売る別の商品・サービス
- `遠い事業`：買い手の事業とほとんど関係がない

買い手の事業は、`acquirer` の名前・`acquirer_industry`・`reason` の書き方から判断する。

## 出力

出力ファイルに Write で JSON を1つ書く。入力の全行について1要素ずつ、入力と同じ順で出す。key は入力の文字列をそのまま写す。

```json
[{"key": "123-E01234", "purpose": "同じ事業の拡大", "relatedness": "同じ事業"}]
```

書いた後に、出力の件数と key の並びが入力と同じかを見比べる。最後に、件数を1行で返す。
