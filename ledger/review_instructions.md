# 抜き出した取得の案件を原文と見比べて採点する

入力ファイル（JSONL、1行1注記）を Read で全部読む。各行には次が入っている。

- `docID`・`filerName`・`element`
- `text`：有報の「企業結合等関係」の注記の原文
- `extracted`：別の担当がこの注記から「取得」として抜き出した案件の一覧

コードやスクリプトは書かない・実行しない。原文を自分で読んで判断する。

項目の定義は、抜き出しの担当への指示書 `ledger/claude_deals_instructions.md` の「案件の項目」と「守ること」に従う。最初に読む。

## 手順（注記ごと）

1. 原文を読み、**グループ外の会社・事業の支配を新たに獲得した案件（指示書の kind が「取得」に当たるもの）** を自分で全部挙げる。これを正解の一覧とする。指示書で「その他」とするもの（前期の取得の暫定処理の確定だけの記載など）は入れない
2. 正解の一覧の案件ごとに：
   - `found`：`extracted` にその案件があるか。名前の表記の揺れは同じ案件とみなす
   - 次の5項目の正誤を `fields` に書く：`acquisition_date`・`voting_ratio`・`consideration`・`goodwill`・`assets_total`
     - `"正"`：原文の正しい値と一致する。金額は単位を考えて同じ額なら正。全角・半角やカンマの違いは問わない。指示書の定義で null が正しい項目（書かれていない、複数の取得の合算でしか書かれていない、外貨だけで書かれている、負ののれん）を null にしていれば正
     - `"誤"`：違う値、書かれているのに null、null が正しいのに値を入れた、のどれか
     - `found` が false なら、5項目とも `"誤"`
     - `correct` に正しい値を短く書く（例「1,410百万円」「null（合算のみ）」）
     - 迷った項目は `reason` に理由を1文で書く。迷わなければ書かない
3. `extracted` にあるのに正解の一覧に無い案件（グループ内の再編を取得とした、作り話、同じ案件を2件にした、など）を `false_acquisitions` に名前で挙げる

## 出力

出力ファイルに Write で JSON を1つ書く。入力の全行について1要素ずつ、入力と同じ順で出す。`docID` と `element` は入力のものを写す。

```json
[
  {"docID": "...", "element": "...",
   "acquisitions": [
     {"name": "...", "found": true,
      "fields": {"consideration": {"verdict": "正", "correct": "1,410百万円"}, "goodwill": {"verdict": "誤", "correct": "121百万円", "reason": "..."}, ...5項目}}
   ],
   "false_acquisitions": []}
]
```

取得の案件が無い注記は `"acquisitions": []`。

最後に、注記数・正解の取得の数・見落とし・取得でないのに取得とした数を1行で返す。
